Guide

Before you start

Kumoji drives rclone; it does not replace it. So you need:

  • rclone installed — brew install rclone;
  • an rclone configuration, in ~/.config/rclone/rclone.conf. It is rclone config that creates the remotes. Encrypted or not: Kumoji detects it, and only asks for a password if your configuration has one.

If rclone is missing, Kumoji tells you on the very first command, with the line to type — it will not ask for a fingerprint for nothing.

Installing

Unzip the archive, drag Kumoji.app into your Applications folder, then open it. The application is signed and notarised by Apple: it starts without a warning.

Kumoji does not appear in the Dock. Look for its cloud in the menu bar, at the top right of the screen — it fills in as soon as a volume is mounted. Everything is driven from that menu; the application has no window.

First run

A single step: 🔄 Load configuration… What follows depends on what Kumoji finds.

  • unencrypted configuration — nothing else to do. No password is asked for, no fingerprint, and the two menu entries concerning them do not appear.
  • encrypted configuration — Kumoji asks for the password, checks it against your configuration, then puts it in the keychain, where TouchID protects it. A password that decrypts nothing never gets in.

Kumoji then reads the list of your remotes. It keeps only their names and paths: no token, no credential touches the disk. It is that cached list which lets you open the menu and unmount without ever being asked for the password again.

When you change your rclone.conf, the menu offers to reload it — it compares the dates. And if you have changed its password, that is where Kumoji will tell you: it then discards the one it was keeping, now useless, and asks for the new one.

🔑 Set the rclone password… stays available to change it at any time. It is checked on every entry.

Mounting, unmounting

  • 🔴 red — not mounted. The submenu offers 🎣 Mount.
  • 🟡 yellow — the mount has started, the kernel does not see it yet. A few seconds, nothing to do.
  • 🔵 blue — mounted. The submenu opens the volume in the Finder, or unmounts it.

Volumes appear in ~/rclonedisk/, one folder per remote, and in the Finder like any network disk.

A mount that fails opens an alert carrying the last lines of rclone's log: the exact reason, without having to go looking for it.

Under each mounted volume, two grey lines: the free space on the remote storage, when it reports a quota, and the uploads in progress — pending files, amount sent, speed. They update while the menu is open, and the cloud in the menu bar gets an arrow while an upload runs.

Unmounting a volume that has not finished uploading asks for confirmation. If you unmount anyway, nothing is lost: the files stay in the local cache and are uploaded at the next mount.

The fingerprint, and the delay

After the first mount, Kumoji keeps the password in memory for eight hours by default. During that time, mounting and unmounting costs nothing.

🔒 Lock now forgets it immediately — the entry only appears when there is actually something to forget. The delay can be set (see below): 0 to never keep the secret, any duration otherwise.

As long as a volume is mounted, the corresponding rclone process holds your decrypted configuration anyway. The delay bounds what Kumoji keeps, not what rclone keeps: unmounting is the only act that really closes the door.

The mount options

⚙️ Edit mount options… opens a text file in your editor. It is re-read on every mount: no need to restart anything to try something else. 

[mounter]                     # application settings, not rclone's
password-ttl 8h               # 30m, 60s, 0 to never keep it
rclone-binary /opt/homebrew/bin/rclone

[common]                      # added to every mount
--vfs-cache-mode full
--vfs-cache-max-size 20G

[exclusive]                   # added to remotes suffixed -exclusive
--dir-cache-time 9999h

One option per line, its arguments separated by spaces — no equals sign. Anything after a # is a comment. Deleting the file regenerates it, commented.

A line Kumoji does not understand is ignored, and it says so in its application log. If a setting seems to have no effect, that is the first place to look.

On an Intel Mac, set rclone-binary to /usr/local/bin/rclone: Homebrew does not install to the same place there.

Two naming conventions

Kumoji reads two things in the names of your remotes — no checkbox to tick, the name is enough.

  • -exclusive — you guarantee that this storage only changes through this mount. Kumoji then adds the options from the [exclusive] section, the ones that freeze caches and make the volume far faster. The suffix disappears from the displayed name and from the folder.
  • -raw, -intermediate, -hidden, -local — the remote does not appear in the menu. That is what you want for those that exist only to encrypt another: one never mounts the layer underneath.

At login

Launch at login, in the menu, puts Kumoji in the menu bar as soon as your session opens. It mounts nothing for all that: mounting stays a deliberate act.

The state shown is the one macOS knows, re-read every time the menu opens — if you remove Kumoji from System Settings ▸ General ▸ Login Items, the tick disappears by itself.

The logs

📁 Open the log folder leads to ~/Library/Logs/Kumoji/. You will find the application's log there, and one log per remote — that is the one to attach to a report.

No secret is written there: no password, no token, no content from your configuration.

Updates

Kumoji checks for new versions and offers to install them. “🆕 Check for updates…” in the menu forces an immediate check. Every archive is signature-checked before it is installed.

If something goes wrong

Reports go on GitHub. Give the version of Kumoji, the version of macOS, the rclone backend concerned and the last lines of the remote's log: many problems come from the backend rather than the application, and those few lines save a round trip.
