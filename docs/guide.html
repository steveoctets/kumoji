Guide

Avant de commencer

Kumoji pilote rclone ; elle ne le remplace pas. Il vous faut donc :

  • rclone installé — brew install rclone ;
  • une configuration rclone, dans ~/.config/rclone/rclone.conf. C'est rclone config qui crée les remotes. Chiffrée ou non : Kumoji le détecte, et ne demande de mot de passe que si votre configuration en a un.

Si rclone manque, Kumoji vous le dit dès la première commande, avec la ligne à taper — elle ne vous demandera pas d'empreinte pour rien.

Installer

Décompressez l'archive, glissez Kumoji.app dans votre dossier Applications, puis ouvrez-la. L'application est signée et notarisée par Apple : elle démarre sans avertissement.

Kumoji n'apparaît pas dans le Dock. Cherchez son nuage dans la barre des menus, en haut à droite de l'écran — il se remplit dès qu'un volume est monté. Tout se pilote depuis ce menu ; l'application n'a pas de fenêtre.

Premier démarrage

Un seul geste : 🔄 Charger la configuration… La suite dépend de ce que Kumoji trouve.

  • configuration en clair — rien d'autre à faire. Aucun mot de passe n'est demandé, aucune empreinte, et les deux entrées de menu qui les concernent n'apparaissent pas.
  • configuration chiffrée — Kumoji demande le mot de passe, le vérifie contre votre configuration, puis le range dans le trousseau, où TouchID le protège. Un mot de passe qui ne déchiffre rien n'y entre jamais.

Kumoji lit alors la liste de vos remotes. Elle n'en retient que les noms et les chemins : aucun jeton, aucun identifiant ne touche le disque. C'est cette liste mise en cache qui permet d'ouvrir le menu et de démonter sans jamais redemander le mot de passe.

Quand vous modifiez votre rclone.conf, le menu vous propose de la recharger — il compare les dates. Et si vous en avez changé le mot de passe, c'est là que Kumoji vous le dira : elle retire alors celui qu'elle gardait, devenu inutile, et vous demande le nouveau.

🔑 Définir le mot de passe rclone… reste disponible pour le changer à tout moment. Il est éprouvé à chaque saisie.

Monter, démonter

  • 🔴 rouge — pas monté. Le sous-menu propose 🎣 Monter.
  • 🟡 jaune — le montage est lancé, le noyau ne le voit pas encore. Quelques secondes, rien à faire.
  • 🔵 bleu — monté. Le sous-menu ouvre le volume dans le Finder, ou le démonte.

Les volumes apparaissent dans ~/rclonedisk/, un dossier par remote, et dans le Finder comme n'importe quel disque réseau.

Un montage qui échoue ouvre une alerte portant les dernières lignes du journal de rclone : le motif exact, sans avoir à le chercher.

L'empreinte, et le délai

Après le premier montage, Kumoji garde le mot de passe en mémoire pendant huit heures par défaut. Pendant ce temps, monter et démonter ne coûte plus rien.

🔒 Verrouiller maintenant l'oublie immédiatement — l'entrée n'apparaît que lorsqu'il y a effectivement quelque chose à oublier. Le délai se règle (voir plus bas) : 0 pour ne jamais garder le secret, une durée quelconque sinon.

Tant qu'un volume est monté, le processus rclone correspondant détient de toute façon votre configuration déchiffrée. Le délai borne ce que Kumoji garde, pas ce que rclone garde : démonter est le seul geste qui ferme vraiment la porte.

Les options de montage

⚙️ Modifier les options de montage… ouvre un fichier texte dans votre éditeur. Il est relu à chaque montage : inutile de relancer quoi que ce soit pour essayer autre chose. 

[mounter]                     # réglages de l'application, pas de rclone
password-ttl 8h               # 30m, 60s, 0 pour ne jamais garder
rclone-binary /opt/homebrew/bin/rclone

[common]                      # ajoutées à tous les montages
--vfs-cache-mode full
--vfs-cache-max-size 20G

[exclusive]                   # ajoutées aux remotes en -exclusive
--dir-cache-time 9999h

Une option par ligne, ses arguments séparés par des espaces — pas de signe égal. Tout ce qui suit un # est un commentaire. Supprimer le fichier le régénère, commenté.

Une ligne que Kumoji ne comprend pas est ignorée, et le dit dans son journal d'application. Si un réglage semble sans effet, c'est le premier endroit à regarder.

Sur un Mac Intel, réglez rclone-binary sur /usr/local/bin/rclone : Homebrew n'y installe pas au même endroit.

Deux conventions de nommage

Kumoji lit deux choses dans le nom de vos remotes — pas de réglage à cocher, le nom suffit.

  • -exclusive — vous garantissez que ce stockage ne change que par ce montage. Kumoji y ajoute alors les options de la section [exclusive], celles qui gèlent les caches et rendent le volume bien plus rapide. Le suffixe disparaît du nom affiché et du dossier.
  • -raw, -intermediate, -hidden, -local — le remote n'apparaît pas dans le menu. C'est ce qu'il faut pour ceux qui n'existent que pour en chiffrer un autre : on ne monte jamais la couche du dessous.

À l'ouverture de session

Lancer à l'ouverture de session, dans le menu, pose Kumoji dans la barre des menus dès que vous ouvrez votre session. Elle ne monte rien pour autant : le montage reste un geste délibéré.

L'état affiché est celui que connaît macOS, relu à chaque ouverture du menu — si vous retirez Kumoji des Réglages système ▸ Général ▸ Ouverture, la coche disparaît d'elle-même.

Les journaux

📁 Ouvrir le dossier des journaux mène à ~/Library/Logs/Kumoji/. On y trouve le journal de l'application, et un journal par remote — c'est celui-là qu'il faut joindre à un signalement.

Aucun secret n'y est écrit : ni mot de passe, ni jeton, ni contenu de votre configuration.

Mises à jour

Kumoji vérifie les nouvelles versions et vous propose de les installer. « 🆕 Rechercher des mises à jour… » dans le menu force une vérification immédiate. Chaque archive est vérifiée par signature avant d'être installée.

Si quelque chose cloche

Les signalements se déposent sur GitHub. Indiquez la version de Kumoji, celle de macOS, le type de backend rclone concerné et les dernières lignes du journal du remote : beaucoup de problèmes tiennent au backend plutôt qu'à l'application, et ces quelques lignes épargnent un aller-retour.
